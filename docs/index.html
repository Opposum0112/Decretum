Structured intent.

Decretum is a domain-neutral declarative execution compiler. It turns structured intent, schemas, recipes, profiles and available capabilities into a portable machine-readable contract for an external harness or agent to execute.

View on GitHubIssues & discussion

The problem

Execution requirements often end up scattered across scripts, documentation, environment assumptions and provider-specific integrations. That makes workflows harder to validate, reproduce and reason about before anything actually runs.

01 / DEFINE

Capture intent

Represent what a workflow requires without hard-coding the runtime that will execute it.

02 / RESOLVE

Bind capabilities

Discover available implementations and deterministically resolve requirements against a registry and profile.

03 / CONTRACT

Make execution explicit

Emit a portable contract containing the resolved execution boundary, rather than silently executing anything.

04 / DELEGATE

Leave runtime outside

An external harness or agent owns execution, interaction, persistence, evidence and reporting.

The model

Four declarative inputs describe the semantic and execution requirements; the compiler turns them into a resolved contract.

Schema

Defines the semantic boundaries and valid structure of a domain.

Recipe

Describes what should be done: the intended workflow or experiment.

Profile

Expresses execution characteristics, preferences and constraints.

Registry

Describes available providers, capabilities and implementations.

Compile, don't execute

The architectural boundary is deliberate: Decretum resolves intent into an execution contract and then stops.

Schema→Recipe→Profile→Registry→Validate→Discover→Resolve→Policy→Contract
Decretum stops here.

The external harness / agent consumes the execution contract and performs the real work. Storage, evidence, session state and reporting remain outside the compiler.

Define in Decretum. Execute in the harness. Remember in the store.

Small example

A recipe can express a security research workflow without embedding the implementation details of the execution environment.

name: web-research-experiment domain: security-research requirements: - isolated_compute - network_capture - evidence_integrity policy: approval: required # Decretum resolves these requirements into a machine-readable contract. # A separate harness decides how to execute that contract.

Domain-neutral by design

Security research is a reference domain, not the architectural boundary. The same compilation model can describe other structured execution workflows.

Decretum + Cusimanse

The projects occupy complementary boundaries.

Decretum

Cusimanse

Research requirements → controlled disposable execution → collected, verified and preserved evidence.

Project status

Decretum is a beta hobby / open-source project, actively evolving and developed in spare time. It is experimental and not positioned as production-ready software.
